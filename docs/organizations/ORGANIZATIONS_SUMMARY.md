## Organization Roles Explained

### Owner (1-2 people)

**Full control over everything:**
- Manage all settings
- Add/remove users
- Assign all roles (including Owner)
- Delete organization
- View all items

**Best for:** CEO, CTO, IT Director

---

### Admin (2-5 people)

**Full management except deleting org:**
- Add/remove users (except Owners)
- Assign roles (except Owner)
- Manage collections and groups
- View all items

**Best for:** IT Managers, Security Team

---

### Manager (5-10% of users)

**Collection-level management:**
- Create and manage specific collections
- Assign users to their collections
- Cannot view all items
- Cannot manage organization

**Best for:** Department Managers, Team Leads

---

### User (Most team members)

**Standard access:**
- Access assigned collections
- Add/edit items (if permitted)
- Cannot manage users or collections
- Cannot view unassigned collections

**Best for:** Employees, contractors

## Collections Explained

**What are collections?**

Logical folders that organize shared passwords and control access.

**Examples:**

**By Department:**
- HR Collection → HR Team can access
- Engineering Collection → Engineers can access
- Finance Collection → Finance Team can access

**By Project:**
- Project Alpha → Project Alpha Team
- Project Beta → Project Beta Team
- Client X → Client X Account Team

**By Environment:**
- Production Servers → Senior Engineers only
- Staging Servers → All Engineers
- Development Tools → All Engineers

**Permissions per collection:**
- **Can View** - Read-only access
- **Can View & Edit** - Modify existing
- **Can View, Edit & Add** - Full access (except delete collection)

---

## Groups Explained

**What are groups?**

Collections of users for easier permission management.

**Example:**

Instead of assigning 20 engineers individually to 5 collections (100 assignments), create "Engineering" group, add 20 engineers once, assign group to 5 collections (5 assignments).

**Benefits:**
- New hire? Add to group → instant access
- Employee leaves? Remove from group → instant revocation
- Change permissions? Update group → affects all members
- 95% less work for large teams

**Recommendation:** Use groups for organizations with 20+ users

## Security Best Practices

### Must-Do (High Priority)

✅ **Enable 2FA policy** - Require all users to enable two-factor auth  
✅ **Set master password policy** - Minimum 14 characters, complexity requirements  
✅ **Limit Owner/Admin roles** - Only 2-5 people need admin access  
✅ **Grant least privilege** - Users only see what they need  
✅ **Immediate offboarding** - Remove access when employee leaves  

### Should-Do (Medium Priority)

✅ **Use groups** - Simplify permission management (if > 20 users)  
✅ **Review event logs** - Monthly security audits  
✅ **Configure emergency access** - Business continuity planning  
✅ **Document procedures** - Onboarding, offboarding, access requests  
✅ **Train users** - Security awareness  

### Nice-to-Have (Low Priority)

✅ **LDAP sync** - Automate user provisioning (if using Active Directory)  
✅ **Password generator policy** - Standardize password generation  
✅ **Regular access reviews** - Quarterly permission audits
